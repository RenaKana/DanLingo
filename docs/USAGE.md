# 使用说明

先按根目录 README 构建并加载 `.output/chrome-mv3`。当前是开发候选，网站改版或未知播放器构建可能使适配不可用。

## 在线翻译

1. 在设置中选择远程后端，填写兼容 Chat Completions 的地址。
2. 输入自己的 Key；按需选择是否记住。模型可获取列表或手动填写。
3. 使用“测试模型”检查当前填写的配置，再“保存并授权服务”。服务授权由浏览器确认。
4. 打开受支持页面，用弹窗启用翻译。更新后重新加载扩展并刷新页面。

服务的并发、批量、超时、思考强度和模型限制会影响速度与费用。性能测试会发送额外请求，真实服务可能计费；少量样本不代表持续直播吞吐。

在线每日请求上限默认 3000 次，可在设置页改为正整数并保存。同一浏览器配置中的扩展按本机自然日累计计数，所有标签页和服务共享，刷新、切换服务和重启后台不会清零。重试、补翻、模型测试和性能测试均计入；缓存命中、合并请求、本地推理和获取模型列表不计入。预占成功后取消可能仍计入；已发送的失败请求不退次数。

设置页和弹窗显示当天已用与剩余次数。到达上限或计数存储不可用时停止新增在线发送并保留原文；次日或调高上限后允许新请求，不自动重播历史直播消息。该设置限制请求次数，不是金额上限；请同时在服务方设置费用限额。

公网服务需要 HTTPS。本地 HTTP 必须显式启用，只允许 localhost、127.0.0.1 或私有 IPv4；更换协议、域名或端口后需要重新配置对应 Key。

## 普通视频

Niconico 默认优先当前位置和缓冲区，再准备整个已读取评论池；可改为仅提前 N 秒。准备不会暂停或跳转视频，来不及完成时保留原文。

Bilibili 仅对已审核播放器构建及当前 CID 已解码分段工作。分 P 按资源隔离，进度不代表已取得整个视频的全部弹幕。高级、脚本、图片及无法确认的样式保持原样。

## 直播与补翻

直播按有限缓冲释放译文或原文。普通迟到结果不改写已释放屏幕弹幕。补翻、强制重译和醒目留言覆盖依赖平台能否确认原始消息身份。

Bilibili 文字与内联表情保留各自位置，纯表情和未知效果保持原样。聊天与屏幕弹幕共享翻译，聊天补翻可更新仍在页面内的正文；已消失的屏幕弹幕不会重新发射。超时自动补翻一次默认关闭，第二轮预算与显示方式由设置控制。

一键补翻针对点击时的消息和有限近期记录，不抓取无限历史。YouTube 置顶、付费消息与 Bilibili 醒目留言不能仅凭普通聊天成功推定全部覆盖。遇到网站验证码时按网站流程手动处理。

## 本地模型

切换本地后端后选择 GGUF 文件或目录。模型由用户提供，许可证由模型作者规定。扩展使用本地 GPU/内存；模型体积、上下文和并行槽数影响占用，先选择设备可承受的配置。

目录授权来自浏览器，重启后可能需要再次确认。移动或替换文件后应重新扫描、选择或加载。清单最低浏览器版本不保证 WebGPU、JSPI、驱动和任意 GGUF 架构兼容。

添加、手动刷新和加载外部文件／目录时，会分块读取全部内容并计算指纹，显示核验进度，可取消；大模型需要相应磁盘读取时间。即使大小和修改时间没变，内容替换也会被识别。加载使用已核验的同一组文件对象；普通列表刷新和已加载模型的逐条翻译不会重复读取整个模型。

内容变化或旧外部记录首次补算指纹时，会更换模型身份，旧身份下的译文不会作为新模型的缓存命中；需要重新选择、加载时界面会保留相应状态。不会自动删除用户权重，也不会清空所有模型的译文缓存。

## 排查与数据管理

- 无译文：检查扩展开关、平台诊断、目标语言、服务授权和模型测试结果。
- 超时或限流：检查 Provider 的预算和限额；增加并发不一定提高及时率。
- 本地加载失败：检查显存、浏览器能力、文件授权及模型状态；文件名识别不是完整架构兼容证明。
- 更新后异常：重新加载扩展并刷新页面，避免旧内容脚本与新后台混用。
- 清除数据：Key 删除、译文缓存清空和本地模型／目录管理是不同操作；启用翻译时可能继续产生缓存。

报告问题时提供版本、浏览器、平台和复现步骤，不上传 Key、个人浏览器配置、真实服务配置、整页抓取或含个人聊天的日志。
