# 使用说明

本说明适用于 0.5.20 正式版。也可按根目录 README 从独立克隆构建并加载 `.output/chrome-mv3`；该流程不适用于本机固定工作区。网站改版或未知播放器构建可能使适配不可用。

## 安装 ZIP

1. 将 `DanLingo-0.5.20-chromium.zip` 解压到准备长期保留的文件夹；根目录应有 `manifest.json`，不要直接加载 ZIP。
2. 打开 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions`，启用开发者模式。
3. 点击“加载已解压的扩展”，选择含 `manifest.json` 的文件夹。
4. 打开独立的扩展设置页面，配置自己的在线服务或本地模型，然后刷新视频／直播页面并启用翻译。

更新时先关闭翻译，将新包解压后替换同一安装文件夹中的文件，在扩展管理页点击重新加载，再刷新网站页面。保留同一文件夹和扩展身份可保留设置；不要通过卸载重装来更新，也不要删除浏览器中的模型／目录授权记录。

## 本机固定工作区

本机固定工作区位于 `D:\Tool\DanLingo-Workspace`。首次在 Chrome 或 Edge 选择“加载已解压的扩展”时，导入测试版 `D:\Tool\DanLingo-Workspace\testing\current\extension` 或正式版 `D:\Tool\DanLingo-Workspace\releases\current\extension`。保留旧扩展和浏览器数据；若作为新安装，可能需要重新填写服务配置、登记模型并授予服务与模型所需授权。首次导入后，后续只在扩展管理页点击“重新加载”，不要重新导入快照或临时构建目录。开发任务默认在收尾时更新测试版；详细更新规则见[开发指南](DEVELOPMENT.md)。

## 在线翻译

新安装时，在线服务地址和模型名称为空，配置档位默认为“自动”。填写自己的服务地址、模型和 Key，再测试、保存并授权；已有设置会在更新后保留。单独加载本地模型不会一并保存其他尚未提交的设置草稿。

弹窗和设置页都可选择目标语言，共用 9 个预设，并支持输入自定义目标语言；此选择同时用于在线和本地翻译。

获取模型时发现的思考能力按服务接口和 Key 隔离保存，不会仅因经过 24 小时而失效。重新获取模型成功后，以服务返回的最新能力替换旧记录；查询失败保留上次成功记录。若服务实际改变了模型能力，可重新获取模型并检查思考选项。

1. 在设置中选择远程后端，填写兼容 Chat Completions 的地址。
2. 输入自己的 Key；按需选择是否记住。模型可获取列表或手动填写。
3. 使用“测试模型”检查当前填写的配置，再“保存并授权服务”。服务授权由浏览器确认。
4. 打开受支持页面，用弹窗启用翻译。Bilibili 视频也可使用全屏或非全屏控制栏的翻译按钮；默认快捷键为 Alt+T，可从设置页“翻译服务”中的快捷键入口前往浏览器修改。更新后重新加载扩展并刷新页面。

在线与本地并发分别设置，新安装时默认各为 2；升级时保留已有并发设置。提高在线并发通常能提升请求吞吐。本地并发受设备与模型推理能力影响，并发更高不一定更快，过高还会增加排队等待；应按本机实测调整，不要直接沿用在线并发值。服务的批量、超时、思考强度和模型限制也会影响速度与费用。性能测试会发送额外请求，真实服务可能计费；少量样本不代表持续直播吞吐。

在线每日请求上限默认 0（不限）；设为正整数后才启用上限。升级时已保存的正值会保留。同一浏览器配置中的扩展按本机自然日累计计数，所有标签页和服务共享，刷新、切换服务和重启后台不会清零。重试、补翻、模型测试和性能测试均计入；缓存命中、合并请求、本地推理和获取模型列表不计入。预占成功后取消可能仍计入；已发送的失败请求不退次数。

设置页和弹窗显示当天用量及限额状态。达到已设置的正值上限或计数存储不可用时停止新增在线发送并保留原文；次日或调高上限后允许新请求，不自动重播历史直播消息。该设置限制请求次数，不是金额上限；请同时在服务方设置费用限额。

公网服务需要 HTTPS。本地 HTTP 必须显式启用，只允许 localhost、127.0.0.1 或私有 IPv4；更换协议、域名或端口后需要重新配置对应 Key。

## 普通视频

Niconico 默认优先当前位置和缓冲区，再准备整个已读取评论池；可改为仅提前 N 秒。准备不会暂停或跳转视频，来不及完成时保留原文。

Bilibili 仅对已审核播放器构建及当前 CID 已解码分段工作。分 P 按资源隔离，进度不代表已取得整个视频的全部弹幕。高级、脚本、图片及无法确认的样式保持原样。

## 直播与补翻

直播按有限缓冲释放译文或原文。普通迟到结果不改写已释放屏幕弹幕。补翻、强制重译和醒目留言覆盖依赖平台能否确认原始消息身份。

Bilibili 文字与内联表情保留各自位置，纯表情和未知效果保持原样。聊天与屏幕弹幕共享翻译，聊天补翻可更新仍在页面内的正文；已消失的屏幕弹幕不会重新发射。直播首轮默认最多等待 3 秒，可调整；各平台的超时自动补翻开关彼此独立且默认关闭。开启后，第二轮自身最多等待 4 秒（首轮设置 3 秒 + 额外设置 1 秒），第二轮等待和显示方式均可调整。

一键补翻针对点击时的消息和有限近期记录，不抓取无限历史。YouTube 置顶、付费消息与 Bilibili 醒目留言不能仅凭普通聊天成功推定全部覆盖。遇到网站验证码时按网站流程手动处理。

## 本地模型

切换本地后端后，在模型来源区点击“添加文件夹”并通过系统目录选择器授予只读访问，或点击“添加文件”一次多选 GGUF 文件。直接选文件适用于单文件模型或组成同一模型的多个分片。列表会用来源标记区分目录与直接选择的文件。模型由用户提供，许可证由模型作者规定；扩展使用本地 GPU/内存，模型体积、量化、上下文和并行槽数都会影响占用。较大的模型通常需要更多设备资源，先从较小的配置尝试；具体兼容性和翻译质量需在你的环境中验证。本地模型闲置自动卸载默认开启，等待 5 分钟；可关闭或调整等待时间。

模型管理列表默认展开。每行按“加载模型”“移除”排列；点击“加载模型”会保存该模型选择并开始加载，不会一并保存其他尚未提交的设置草稿。加载期间可取消，已加载后可卸载。若文件有变化，点击“手动刷新”重新扫描。按浏览器要求重新授权目录时，仍使用只读访问。

目录授权来自浏览器，重启后可能需要再次确认。移动或替换文件后应重新扫描、选择或加载。清单最低浏览器版本不保证 WebGPU、JSPI、驱动和任意 GGUF 架构兼容。

首次添加外部文件／目录时按需读取 GGUF 头部，并保存识别结果与分片顺序。手动刷新和加载只快速检查读取权限、文件大小与修改时间；未变化时复用识别结果，缺少必要元数据的旧记录仅补读一次。此检查不计算整文件指纹，因此不会检测大小和修改时间均未改变的内容替换。界面分别显示目录枚举、文件获取、头部识别、登记和权重加载的阶段与耗时。

检测到文件变化后，该记录不可加载；手动刷新会生成新的模型身份，旧身份下的译文不会作为新模型的缓存命中。文件未变的重新授权及旧记录元数据补全保留身份。选择文件后先取得只读授权，再从实际加载准备路径确认可读，才显示添加成功；浏览器撤销授权后需在授权页重新授权。原文件始终留在原目录，加载时临时传递文件对象，不保存权重副本。

## 排查与数据管理

- 无译文：检查扩展开关、平台诊断、目标语言、服务授权和模型测试结果。
- 超时或限流：检查 Provider 的预算和限额；增加并发不一定提高及时率。
- 本地加载失败：检查内存／显存、浏览器能力、文件授权及模型状态；文件名识别不是完整架构兼容证明。
- 更新后异常：重新加载扩展并刷新页面，避免旧内容脚本与新后台混用。
- 清除数据：Key 删除、译文缓存清空和本地模型／目录管理是不同操作；移除登记不会删除原始模型文件，但移除正在使用的模型会先卸载并清空选择。启用翻译时可能继续产生缓存。

报告问题时提供版本、浏览器、平台和复现步骤，不上传 Key、个人浏览器配置、真实服务配置、整页抓取或含个人聊天的日志。
