# GitHub 发布准备

目标首发为 v0.3.0，提供源码和 Chrome／Edge 手动加载 ZIP，不包含商店发布。当前包版本仍为 0.2.0 开发候选；完整门槛见 [首发验收表](RELEASE_VALIDATION.md)。发布时按文件清单核对上传范围，不依靠忽略规则推断内容。

## 生成候选

```sh
pnpm run check:source
pnpm run prepare:github
```

生成新的 `.artifacts/github-prep/source-*/repository` 和同级 `manifest.json`。清单记录每个文件的大小和 SHA-256；候选包括源码、离线测试、开发工具、选定维护文档、CI 与已固定来源的运行时。不包含本地凭据、生成目录、旧 ZIP、浏览器资料、模型权重和历史验收报告。

生成器不会初始化 Git、创建提交、配置远端、推送或发布。有 Git 仓库时，它同时检查实际暂存文件和暂存字节，禁止忽略文件被强行暂存后绕过检查。源文件修改后应重新生成候选。在候选目录按 [开发步骤](DEVELOPMENT.md) 安装与验证，确认它不依赖私人工作目录的生成物。

## 发布流程

1. **确定所有者并建立私有预检仓库。** 仓库地址为 `dabao12123/DanLingo`，分支为 `main`，版权署名为 `Rena`。先以私有仓库运行预检；包元数据与文档链接均使用实际 GitHub 用户名 `dabao12123`。
2. **核对公开材料。** 原创代码使用 [MIT License](../LICENSE)。公开回归只使用自编合成样本，原始弹幕、网站源码节选和查询报告不进入 Git 历史。真实验证工具显式接收外部录制输入，采集结果保存在被排除的 `.artifacts`。
3. **完成构建与许可核验。** 检查完整原生构建的传递依赖声明，重建固定输入并比对产物；Windows、Linux 的真实 GitHub CI 必须通过。维护者可手动运行 [Native reproducibility](../.github/workflows/native-build.yml)，在隔离环境中使用同一固定镜像重建，核对 JS、WASM 和符号表的大小与 SHA-256，并下载保存构建证据。CI 使用只读仓库权限，不调用真实服务或自动发布。
4. **固定最终候选并验收。** 统一包与清单版本为 `0.3.0`，固定候选提交，完成 [20 格真实场景及特殊消息验收](RELEASE_VALIDATION.md)。浏览器安装、网站消息处理和真实 Provider/GPU 表现不能由离线测试替代。
5. **制作并审查发布资产。** 从最终提交构建 `DanLingo-0.3.0-chromium.zip`、`SHA256SUMS` 和发布说明。ZIP 根目录含 `manifest.json`、`LICENSE.txt` 与 `THIRD_PARTY_NOTICES.txt`，并附原生依赖许可；不含凭据、权重和原始录制。
6. **维护者确认后发布。** 展示最终变更、验收矩阵、已知限制和资产清单，经确认后公开仓库、创建 `v0.3.0` 标签和正式 Release。启用适用的分支保护、安全报告渠道和依赖告警；公开下载的哈希须与验收包一致。有问题的资产撤下后发布修订版本，不覆盖已发布标签。

## 已知限制与安全边界

- 平台主世界通过网页消息桥交付事件，同一网页脚本可伪造形状正确的事件；来源标签和消息 nonce 不构成同源脚本之间的安全隔离。用户启用并授权服务后，页面控制的数据可能触发翻译和相应消耗。每日请求上限是次数限制，费用额度仍应在服务方设置。
- 本地模型内容身份、加载前核验和取消行为是首发必验项；大文件的核验时间取决于磁盘和文件大小。不得仅凭路径、大小、修改时间判定内容未变。
- 可选浏览器工具使用明确配置或已安装环境，不自动下载浏览器。隔离 Chromium、模拟服务和合成消息检查不能作为 Chrome／Edge、真实 Provider 或真实平台验收。

源码检查仅扫描候选字节中的常见令牌特征和可识别的本地测试 Key，不扫描 Git 历史，不证明所有敏感信息或版权问题都已排除。
