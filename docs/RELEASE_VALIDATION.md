## 必须逐项验证的行为

- 启停、刷新、换视频／换房、后台重启、原文超时回退、补翻、缓存和重复消息身份。
- 不得跨资源回写、丢失原文、重复发射，或停止后继续发起请求。
- 每日额度并发、跨日、重启、调高限额及存储失败；所有在线收费入口均受限，本地推理和缓存不消耗额度。
- 外部模型同大小同修改时间替换、分片、取消、失权、旧记录首次迁移与加载时内容核验。

| 特殊消息 | 必须记录 | 状态 |

| 内联表情 | 自然样本、图文顺序、原生图片与交互、翻译失败回退 | 未验收 |
| 置顶消息 | 自然样本、正文、身份、更新和取消置顶 | 未验收 |
| 付费留言 | 自然样本、金额和原生卡片样式、正文及身份 | 未验收 |
| 其他已实现卡片 | 按平台和消息类型列出自然样本及原生交互 | 未验收 |

上表各项需记录实际平台与浏览器，不能以一种普通消息的结果覆盖其他类型。缺少自然样本记为未完成。

## 发布门槛

1. 固定最终提交，完整离线回归、类型检查、浏览器存储检查与构建通过。
2. Windows 和 Linux 的真实 GitHub CI 从冻结锁文件安装并构建通过。
3. 项目与传递依赖许可、素材来源核对完成；固定输入的原生重建与随包产物比对完成。
4. 上述 20 格、关键行为及特殊消息验收完成，且人工日常使用验收确认。
5. 发布包检查通过：根目录含 manifest.json、项目许可证及第三方声明，不含凭据、权重和原始录制材料。
6. 从最终提交生成 DanLingo-0.3.0-chromium.zip、SHA256SUMS 和发布说明，公开下载哈希与验收包一致。
7. 维护者确认最终变更、矩阵、限制及资产后，才公开仓库并发布 v0.3.0。已发布标签不覆盖。

真实服务测试须先明确目标、请求预算与停止条件；验证码、登录、自然特殊消息观察和最终日常使用由维护者参与。离线与模拟检查只证明其直接覆盖的行为。
